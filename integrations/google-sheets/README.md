# ใช้ Google Sheets เป็นฐานข้อมูลของเว็บ

ทุกอย่างของเว็บเก็บอยู่ใน Google Sheet เดียว:

| แท็บ / ที่เก็บ | เก็บอะไร |
| --- | --- |
| แท็บ **Orders** | คำสั่งซื้อ (1 แถว = 1 ออเดอร์) |
| แท็บ **Products** | สินค้า Shopee ที่โชว์บนหน้าแรก |
| แท็บ **Consent** | บันทึกการยอมรับคุกกี้ (PDPA) |
| โฟลเดอร์ **PB3D Payment Slips** ใน Google Drive | ไฟล์สลิปโอนเงิน (private เห็นได้คนเดียว) |

เว็บไม่ได้เชื่อมกับชีตโดยตรง เว็บเรียก **Google Apps Script** (ไฟล์ `Code.gs`) ที่ผูกอยู่กับชีต และต้องส่งรหัสลับไปด้วยทุกครั้ง ส่วนเบราว์เซอร์ของลูกค้าไม่มีทางเข้าถึงชีตได้เลย

ใช้งานฟรี ใช้แค่บัญชี Google ปกติ

---

## สิ่งที่ต้องทำ (ครั้งเดียว ประมาณ 10 นาที)

### 1. สร้างชีต
1. เปิด <https://sheets.new> แล้วตั้งชื่อ เช่น **PB3D Database**
2. **ห้ามแชร์ชีตแบบ "ทุกคนที่มีลิงก์"** เพราะในชีตมีชื่อ เบอร์โทร และที่อยู่ลูกค้า (แชร์ให้ทีมงานทีละอีเมลได้)

### 2. ใส่สคริปต์
1. ในชีต ไปที่เมนู **Extensions (ส่วนขยาย) → Apps Script**
2. ลบโค้ดเดิมทั้งหมด แล้ววางโค้ดจากไฟล์ `integrations/google-sheets/Code.gs`
3. กด 💾 **Save**

### 3. กด Run `setup` ครั้งเดียว
1. ที่แถบด้านบนของ Apps Script เลือกฟังก์ชัน **setup** จากช่อง dropdown แล้วกด ▶ **Run**
2. Google จะขอสิทธิ์: กด **Review permissions** แล้วเลือกบัญชีของคุณ
   - ถ้าขึ้นหน้า "Google hasn't verified this app" ให้กด **Advanced → Go to … (unsafe)** สคริปต์นี้เป็นของคุณเอง จึงปลอดภัย
   - สคริปต์ขอสิทธิ์ใช้ชีตนี้ และขอสิทธิ์ Drive เพื่อเก็บไฟล์สลิป
3. ที่ช่อง **Execution log** ด้านล่าง จะมีรหัสลับยาว 64 ตัวอักษร **คัดลอกเก็บไว้** ใช้ในขั้นที่ 5
   - สคริปต์จะสร้างแท็บ Orders / Products / Consent และโฟลเดอร์ PB3D Payment Slips ให้เอง
   - กด Run ซ้ำได้ รหัสลับจะเป็นค่าเดิม

### 4. Deploy เป็น Web app
1. กด **Deploy → New deployment**
2. กด ⚙️ ข้าง "Select type" แล้วเลือก **Web app**
3. ตั้งค่า:
   - **Execute as: Me** (สคริปต์ทำงานด้วยบัญชีของคุณ)
   - **Who has access: Anyone** (เพื่อให้เว็บเรียกได้ ส่วนรหัสลับในขั้นที่ 3 จะกันคนอื่นไว้)
4. กด **Deploy** แล้วคัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)
5. ตรวจสอบ: เปิด URL นั้นในเบราว์เซอร์ ต้องเห็น `{"ok":true,"service":"pb3d-sheets-backend"}`

### 5. ตั้งค่าบน Vercel
ไปที่ Vercel → Project → **Settings → Environment Variables**

**เพิ่ม 2 ตัวนี้** (Environment: Production, Preview, Development):

| Name | Value |
| --- | --- |
| `GOOGLE_SHEETS_WEBHOOK_URL` | Web app URL จากขั้นที่ 4 (ไม่ใส่ก็ได้ ถ้าใช้ URL เดียวกับที่ตั้งไว้ใน `lib/sheetsDb.ts`) |
| `GOOGLE_SHEETS_WEBHOOK_SECRET` | รหัสลับจาก Execution log ในขั้นที่ 3 (ต้องตรงกันทุกตัวอักษร) |

**ต้องมีอีก 2 ตัว** (ถ้ายังไม่มี):

| Name | Value |
| --- | --- |
| `ADMIN_PASSWORD` | รหัสผ่านเข้าหน้าแอดมิน — ถ้าไม่ตั้ง เว็บจริงจะไม่ให้ใครล็อกอินแอดมินได้เลย |
| `NEXTAUTH_SECRET` | ข้อความสุ่มยาว ๆ (เช่นจาก `openssl rand -hex 32`) |

**ลบตัวเก่าของ Supabase** (เว็บไม่ได้ใช้แล้ว):
- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`

จากนั้นไปที่ **Deployments → … → Redeploy**

### 6. ทดสอบ
1. สั่งซื้อจริง 1 ออเดอร์บนเว็บ ใช้ชื่อลูกค้าว่า "ทดสอบ"
2. ดูที่ชีต: ต้องมีแท็บ **Orders** และแถวของออเดอร์นี้
3. อัปโหลดสลิป: ใน Google Drive ต้องมีโฟลเดอร์ **PB3D Payment Slips** และสถานะในชีตเปลี่ยนเป็น `awaiting_verification`
4. เข้าหน้าแอดมิน: ต้องเห็นออเดอร์นี้ กด "ดูสลิป →" ได้ และเปลี่ยนสถานะได้
5. แท็บ **สินค้า Shopee** ในหน้าแอดมิน: ลองเพิ่มสินค้า 1 ชิ้น แล้วดูว่าขึ้นในแท็บ **Products**
6. ทดสอบเสร็จ กดยกเลิกออเดอร์ทดสอบในหน้าแอดมิน หรือลบแถวในชีตได้เลย

### 7. (ถ้ามีข้อมูลเก่าใน Supabase) ย้ายข้อมูล
ทำบนเครื่องของคุณ ต้องมี Node.js 18 ขึ้นไป

ขั้นแรก ทดลองก่อนโดยยังไม่เขียนอะไรลงชีต:
```bash
SUPABASE_URL=https://xxxx.supabase.co \
SUPABASE_SERVICE_ROLE_KEY=ใส่-service-role-key \
GOOGLE_SHEETS_WEBHOOK_URL=ใส่-web-app-url \
GOOGLE_SHEETS_WEBHOOK_SECRET=ใส่-รหัสลับ \
node scripts/migrate-supabase-to-sheets.mjs --dry-run
```
ถ้าผลออกมาถูกต้อง ให้รันคำสั่งเดิมอีกครั้งโดยตัด `--dry-run` ออก

- สคริปต์ย้าย: ออเดอร์ทั้งหมด, สลิป (ไปไว้ใน Drive), สินค้า Shopee
- รันซ้ำได้ ไม่สร้างข้อมูลซ้ำ
- ย้ายเสร็จแล้ว จะปิดหรือพักโปรเจกต์ Supabase ก็ได้

## จัดการแอดมิน (แท็บ Admins)

ใครเข้าหน้า `/admin` ได้บ้าง กำหนดในแท็บ **Admins** ของชีตนี้ แก้ในชีตแล้วมีผลทันที ไม่ต้อง Redeploy

| อีเมล | รหัสผ่าน | ชื่อ | ปิดใช้งาน |
| --- | --- | --- | --- |
| tansika.p1998@gmail.com | (ตั้งเอง) | | FALSE |

- **เพิ่มแอดมิน:** เพิ่มแถวใหม่ ใส่อีเมลและรหัสผ่าน
- **เปลี่ยนรหัสหรือลืมรหัส:** แก้ช่องรหัสผ่านในแถวนั้น
- **ปิดสิทธิ์ชั่วคราว:** ใส่ `TRUE` ในช่อง "ปิดใช้งาน"
- **ปิดสิทธิ์ถาวร:** ลบแถวนั้นทิ้ง คนที่ล็อกอินค้างอยู่จะหลุดภายใน 12 ชั่วโมง
- ช่องรหัสผ่านว่าง = แถวนั้นล็อกอินไม่ได้
- ใส่รหัสผิด 10 ครั้ง อีเมลนั้นจะถูกล็อก 15 นาที
- ระบบตรวจรหัสผ่านใน Apps Script เท่านั้น และไม่ส่งรหัสออกไปที่เว็บ แต่**ใครเปิดชีตนี้ได้ก็จะเห็นรหัสผ่านทุกคน** จึงไม่ควรใช้รหัสเดียวกับบัญชีอื่น
- **รหัสฉุกเฉิน:** `ADMIN_PASSWORD` ใน Vercel ยังใช้ได้กับอีเมลหลัก 2 อีเมล แม้ Google Sheets จะล่ม

ถ้าเพิ่งอัปเดตมาจากเวอร์ชันที่ยังไม่มีแท็บ Admins ให้ทำตามนี้ก่อน:
1. วางโค้ด `Code.gs` ตัวใหม่ทับของเดิม
2. กด **Deploy → Manage deployments → ✏️ → Version: New version → Deploy** (URL ยังเป็นอันเดิม)
3. รันฟังก์ชัน `setup` อีกครั้ง เพื่อสร้างแท็บ Admins (รหัสลับยังเป็นค่าเดิม)

## การใช้งานชีตประจำวัน

**แก้ไขในชีตได้:**
- เปลี่ยน **สถานะ** ได้จาก dropdown ค่าที่ใช้ได้มีดังนี้:

  | ค่าในชีต | ความหมาย |
  | --- | --- |
  | `pending` | รอชำระเงิน |
  | `awaiting_verification` | ส่งสลิปแล้ว รอตรวจ |
  | `confirmed` | ยืนยันแล้ว |
  | `printing` | กำลังพิมพ์ |
  | `shipped` | จัดส่งแล้ว |
  | `delivered` | ส่งถึงแล้ว |
  | `cancelled` | ยกเลิก |

- ใส่ **เลขพัสดุ** ได้
- เพิ่มคอลัมน์ของตัวเองทางขวาได้ เช่น "Memo" ระบบจะไม่เขียนทับ
- สลับลำดับคอลัมน์ได้ ระบบหาคอลัมน์จากชื่อหัวตาราง

**ห้ามทำ:**
- เปลี่ยนชื่อหัวคอลัมน์เดิม เช่น "Order ID" หรือ "สถานะ"
- แก้ค่าในคอลัมน์ **Order ID** หรือ **สลิป (Drive file ID)**
- เปลี่ยนชื่อแท็บ Orders / Products / Consent

**ความปลอดภัย:**
- ข้อความที่ลูกค้าพิมพ์จะถูกเก็บเป็นตัวอักษรล้วน ไม่มีทางกลายเป็นสูตร (กัน formula injection)
- เบอร์โทรไม่หายเลข 0 ข้างหน้า

## ถ้าแก้ Code.gs ภายหลัง
กด **Deploy → Manage deployments → ✏️ → Version: New version → Deploy**

URL จะยังเป็นอันเดิม ถ้าไปกด "New deployment" จะได้ URL ใหม่ และต้องไปแก้ `GOOGLE_SHEETS_WEBHOOK_URL` บน Vercel ด้วย

## ข้อจำกัดที่ควรรู้
- **ช้ากว่า Supabase:** การสั่งซื้อหรือการโหลดหน้าแอดมินจะใช้เวลาประมาณ 1–3 วินาทีต่อครั้ง (Google Apps Script ช่วงที่ไม่มีใครใช้งานนานจะตอบช้ากว่าปกติ)
- **โควตาฟรีของ Google:** สคริปต์ทำงานพร้อมกันได้ราว 30 คำขอ และไฟล์ Drive ใช้พื้นที่ 15 GB ของบัญชี เพียงพอสำหรับร้านขนาดนี้
- **ขนาดสลิป:** ไม่เกิน 4MB ต่อไฟล์ เพราะ Vercel รับข้อมูลได้ไม่เกิน 4.5MB ต่อคำขอ
- **ถ้าออเดอร์เยอะมาก** (หลักหมื่นแถว) หน้าแอดมินจะโหลดช้าลง ถึงตอนนั้นค่อยย้ายออเดอร์เก่าไปเก็บอีกแท็บ

## สำหรับนักพัฒนา (รันในเครื่อง)
ไม่ต้องมี Google Sheet จริง ใส่บรรทัดนี้ใน `.env.local` แล้วรัน `npm run dev`:
```
SHEETS_EMULATOR_FILE=.data/sheets-emulator.json
```
ระบบจะรัน `Code.gs` ตัวจริงในเครื่อง และเก็บข้อมูลลงไฟล์ JSON นั้นแทน

ห้ามตั้งค่านี้บน Vercel
